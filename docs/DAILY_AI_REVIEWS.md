# Jev 每日 AI 巡检

2026-10-25 已随运行时 `3b46529` 发布至 https://bank.jung.edu.pl 。入口：个人中心 → 定时任务 → 每日 AI 巡检。

首页提供「AI 主动关注」及过程详情。额外手动检查需迁移 024；会显示手动来源并保留每日计划。真实自动触发的录屏流程与脚本见 [视频录制](DEMO_VIDEO.md)。

## 流程

用户保存每天的执行时间、可选关注事项和通知方式。后台沿用持久化调度器，网页关闭后仍由 Worker 处理到期任务。每个到期轮次先进入数据库队列，释放事务锁后再请求模型。

1. 查询当前共享模拟账户的真实数据库快照：可用 CNY 余额、整月账面流入/流出、最近七天需核实交易、未来七天订阅、已保存提醒，以及理财持仓。理财估值沿用该账户的演示日期，并与实际日历区分。
2. 调用 TypeSafe 官方原生 `POST https://api.typesafe.ai/v1/systemone`，使用 Jev 的 `Noul` 问题判断本次是否值得主模型进一步分析。这个回答只有 0–1 概率，没有额外的 confidence 字段。
3. 概率不高于 0.2 且没有新的必看事实时，保存安静结果，不请求主模型；不确定或偏向需要分析时，调用现有 `AI_MODEL`。新出现的需核实交易或资金不足等必看事实仍交给主模型处理，不被 Jev 的安静判断遮蔽。原有明确时间提醒独立执行。
4. 主模型使用 `bank-daily-review` Skill，从给定事实中选择最多三项重点。服务端验证事实 ID，并用数据库事实生成最终文字，模型不能生成新的金额、日期、产品或执行成功声明。
5. APP 保存结果；用户选择了有效的已绑定 QQ/企微通知且有关注事项时，向原有 outbox 写入通用通知。外部消息不包含金额、提醒正文或模型上下文，实际送达仍受平台和连接状态影响。

最近七天已提示的事实编号随状态一起交给模型，减少重复提醒。每日巡检只提供关注事项，不预留资金、不下花店订单、不转账或买理财。完整生日记忆、预算预留和模拟商户执行仍需各自业务实现；本任务读取已保存提醒及本任务的关注事项，不读取浏览器访客私有偏好。

## 配置

私有 `.env.local` 或部署私有环境文件中配置：

```dotenv
TYPESAFE_API_KEY=你的私有密钥
TYPESAFE_MODEL=jev-1.13.0
JEV_TIMEOUT_MS=8000
JEV_QUIET_THRESHOLD=0.2
```

主模型继续使用已有 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`，后台使用服务端默认模型。还需要数据库及独立 `SCHEDULER_TOKEN`。

默认固定官方文档列出的稳定版本 `jev-1.13.0`。如改变模型或阈值，应重新观察实际样本，不把“0.2”当作已校准的业务准确率。TypeSafe 的 `jev-latest` 别名可移动；每轮记录实际响应的模型名、概率、阈值、耗时和 token 数。官方来源：[模型与版本](https://docs.typesafe.ai/models)、[Noul 请求与响应](https://docs.typesafe.ai/primitives/noul)、[System One API](https://docs.typesafe.ai/api/system-one)。

先应用 `023_daily_ai_reviews.sql`，再重建 APP 并启动 Worker。Compose 和发布检查已纳入迁移及新环境变量；源码同步不包含本地密钥。自动部署在备份后单独经 SSH 标准输入同步已配置的 Jev 私有变量；手动发布须自行配置。入口仅显示是否已配置，不返回密钥。

## 恢复和记录

- 单轮结果以任务和原定时间唯一标识；每次 tick 最多领取一个 AI 检查。
- 90 秒租约和随机令牌防止并发领取；过期后可恢复。模型请求在事务外进行，资金业务不被远程调用占锁。
- 快照及 Jev 判断分阶段保存，重试可复用；快照超过 30 分钟则重新查询并废弃旧判断，结果展示数据时间。远程请求在网络不确定时可能重复，最终结果和通知队列按轮次去重。
- 短暂失败按 60/120 秒重试，最多三次；缺配置、认证失败或重试耗尽显示失败并将任务置为需处理。没有规则伪装的 Jev 回答，也不在错误时静默调用主模型。
- 暂停、取消或恢复会终止尚未完成的轮次；主模型返回后再次核对任务版本、截止时间和账户状态。旧令牌不能发布结果或通知。
- “本次分析过程”展示 Jev 判断、概率、耗时和主模型请求/成功状态。判断成功不等于主模型成功，结果保存不等于通知送达。
