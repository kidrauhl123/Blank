# BankPilot（AIbanking）安全自评报告

版本：1.0，团队审查稿。评估日期：2026-10-17（Asia/Shanghai）。保密：内部 / 获授权评审。代码基线：`aa1b8d874641e996af403b553a605d297ae49eed`。修复在独立分支，结论针对本次本地测试版本；合并、线上部署和团队签字不能由本报告替代。

## 1. 自评结论

项目具备服务端权限分级、会话隔离、转账事务、双分录和人工授权等基础控制。本次确认三类授权缺口并做最小修复：草稿缺乏统一有效期、已存授权摘要未用于执行前比对、交易 TOTP 可在有效窗口复用。新增九项回归，原有与新增测试合计 **181 项通过、0 项失败、0 项跳过**；另有 **8 项真实 HTTP 边界探针通过**，类型和代码规范检查通过。

本次不作“已达到生产银行安全”“完全防注入”“无高危漏洞”或“符合全部赛题”的结论。共享模拟身份、真实模型对抗未执行、跨草稿总失败限速不足、事实一致性校验不完整、审计缺少独立防篡改存储等风险仍存在。当前适用于受控比赛演示；在真实资金、真实客户或公网生产条件下不可据此直接验收。

## 2. 范围、方法与证据可信度

审查范围为固定 SHA 的 180 个文本文件，重点检查 API、认证、核心银行、页面动作桥接、Agent 与渠道边界、SQL 迁移和部署配置。二进制图像/图标未下载，未审查完整 Git 历史、真实部署密钥、云配置、真实渠道后台或第三方服务内部安全。

代码通过已授权 GitHub 连接读取并在本地重建文本快照；换行格式可能规范化。没有把本地重建的 Git 根提交冒称上游原始提交，远端分支以实际上游 SHA 创建。证据记录本地代码哈希用于复核。依赖沿用项目 package-lock，在本地转换为 pnpm 锁后安装，未提交转换文件；没有新增应用运行时依赖。

测试环境：Windows x64、Node.js 24.19.0、Next.js 16.3.8、Vitest 4.1.11、PostgreSQL 17.6。PostgreSQL 与 Next 测试服务只监听 127.0.0.1，使用隔离数据库与临时模拟账户。模型单元/集成测试使用确定性替身，不调用真实付费模型；HTTP 探针不登录、不提交真实交易。

自评分级采用本项目定性风险矩阵，按影响与利用前提标记高/中/低，未计算 CVSS，也未聘请独立第三方审计。哈希可检查文件是否改变，不能证明签名真实性或替代独立见证。
