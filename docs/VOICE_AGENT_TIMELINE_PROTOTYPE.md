# 语音与 Agent 执行过程：样机及 BankPilot 接入

功能在独立分支 `codex/voice-agent-timeline-prototype` 和草稿 PR #3 开发。开发环境运行 `npm run dev` 后访问 `/preview/voice-trace` 可查看不调用银行 API、数据库或真实 Agent 的独立样机；生产构建中该预览路由返回 404。同一分支也已将语音和时间线接入现有 `FloatingAppAgent`，沿用 `/api/agent/app` 的会话权限与页面动作状态机。此分支尚未合并或部署。草稿 PR #1 的访客偏好与任务范围隔离改动仍需在合并时核对。

## 已实现的交互

- 点击麦克风开始/停止识别，支持普通话 `zh-CN` 与粤语 `zh-HK` 选项。识别结果只进入可编辑文本框，用户核对后点击“核对后发送”；不自动发起任务。识别不可用或权限被拒时保留文字输入。浏览器可能把录音交给外部识别服务，样机本身不上传或保存音频。
- 回复播报由用户手动触发，可停止；默认语速为 0.85。预览只播报可见的演示回复，不播放账户秘密或验证码。
- 结构化时间线展示每步的序号、时间、标题、状态和简要说明。演示可暂停、继续、结束；转账关键词只演示到“等待本人核对”，不会把准备步骤说成真实交易成功。
- `TimelineEvent`、`mergeTimelineEvents` 与展示组件独立于模拟流程。重复事件按 ID 更新，按服务端序号排列。

## BankPilot 接入

1. 悬浮助手复用浏览器语音识别逻辑，识别结果只填写原有输入框；用户可以编辑金额或收款人，必须停录并按“发送”才进入原有 `send` 流程。普通话与粤语可选，浏览器不支持或拒绝权限时保留文字输入。语音播报由用户点击后才播放当前可见的助手回复。浏览器可能自行使用外部识别服务；应用不上传或保存音频。
2. 服务端将任务创建、模型推进、浏览器动作回报、授权、暂停、取消和异常写入既有 `audit_events`。迁移 `017_app_agent_timeline.sql` 为按用户和任务读取增加索引。客户端回报仅作为未验证的浏览器观察，不能说明银行交易成功。
3. `GET /api/agent/app?id=...` 和命令响应在完成现有客户 ID、会话哈希、过期检查后，返回由审计记录确定性映射的最近 150 条时间线事件；GET 禁止缓存。映射只输出固定的安全文案，不把审计证据、模型文本、页面字段或验证码透传。当前分支基于主分支，会话范围按主分支实现；与草稿 PR #1 合并时应保留其更细的访客/profile 范围检查。
4. 悬浮助手展开时显示服务端时间线，收起时显示最近步骤；刷新后按已存任务 ID 重新读取，已完成任务也能恢复。独立样机仍使用模拟事件。既有页面光标、暂停、接管和人工确认交互未改变。

## 验收重点

- 语音：目标浏览器的普通话/粤语识别和播报实测；麦克风拒绝、断网、重复点按、手动改写识别金额或收款人后才发送；切换页面时停止录音与播报。
- 时间线：跨刷新恢复、用户暂停/取消、人工确认等待、模型失败、切换会话后的拒绝访问。真实数据库集成测试需要 PostgreSQL 和本项目的隔离测试账号。
- 银行业务：准备转账不标记为成功；只有受信任的银行回执能显示交易完成。语音不能代点最终确认、读取动态码或绕过现有强验证。

发布前还需在目标浏览器上实测真实麦克风、普通话/粤语识别及播报，并在可用的 PostgreSQL 测试环境运行数据库集成测试。测试环境之外不要使用真实账户进行语音验收。
