# 主动服务视频录制

目标是录到真实页面中的一段完整用户经历：保存生日提醒 → 配置每日检查 → 回到首页 → 后台到期执行 → 首页出现结果 → 打开判断过程及数据依据。

2026-10-22：本地代码已补录制入口，尚无已完成的视频文件。当前会话的服务监听、数据库及外部模型连接条件不具备，实际录制需要已运行新版的环境。

## 页面准备

- 首页新增「AI 主动关注」，每五秒读取实际执行状态，自动显示新的检查结果。
- 详情展示读取数据、Jev 判断、主模型分析、结果保存四个阶段，状态来自实际数据库字段。
- 详情可展开数据依据，与提醒、账户和理财数据核对。
- 「立即检查一次」复用同一后台处理器，便于排练；该轮明确标记为手动触发，不改变每日时间或伪装成自动任务。
- 自动录制脚本使用未来的真实时间等待 Worker 自动执行，不点击手动触发，不修改系统时间或注入模型返回。

需依次执行到 `024_review_recording_support.sql`。023 提供模型巡检，024 保存额外手动请求的幂等键和触发来源。APP、数据库、scheduler、Jev 和主模型须实际可用。

## 主线镜头（约两至三分钟）

| 镜头 | 页面动作 | 画面中要出现的证据 |
| --- | --- | --- |
| 设置目标 | 选择小橘子，保存两天后的爱人生日提醒，文字注明鲜花预算 300 元 | 真实保存的日期、提醒与预算说明 |
| 安排巡检 | 创建每日 AI 巡检，首次时间设在接下来一两分钟 | 下次执行时间、任务已保存 |
| 返回银行 | 回首页，可查看持仓与流水；不向助手发新消息 | 首页的下次检查时间 |
| 后台触发 | 等待计划时间，首页自动出现检查结果 | 本轮来源为“后台定时触发” |
| 展示分工 | 打开账户巡检详情 | 实际 Jev 模型、概率、耗时、主模型执行状态 |
| 核对依据 | 展开本次检查的数据依据 | 已保存的生日提醒、当前账户事实和结果之间的关联 |

等待时段可在后期剪短并明确标注“等待后台任务，已缩时”。只剪除等待，不替换模型输出、日期或成功状态。

生日主线当前展示的是主动发现已保存提醒、整理资金准备关注事项。预算冻结、花店订单与购买支付尚未实现，画面及字幕不宣称“资金已备好”或“鲜花已购买”。

## 自动录制

本机启动示例（私有环境变量须先配置；不把密钥放进命令参数）：

```bash
npm run dev -- --port 3109
```

另一个终端启动后台：

```bash
BANKPILOT_INTERNAL_URL=http://127.0.0.1:3109 npm run scheduler:dev
```

第三个终端录制：

```bash
npm run record:daily-review
```

也可指定已经升级并配置好的测试站：

```bash
BANKPILOT_RECORD_URL=https://your-updated-demo.example npm run record:daily-review
```

默认录制生日场景，1280×960 画布中保留项目原有手机界面。需要可见浏览器时设置 `BANKPILOT_RECORD_HEADLESS=0`；使用系统 Chrome 时通过 `CHROME_PATH` 指定现有可执行文件。脚本不自动安装浏览器。

输出目录 `output/daily-review/<时间>/` 被 Git 忽略，包含：

- `birthday.webm`：实际执行且选中了生日提醒时，标记为该分支成功素材。
- `birthday.incomplete.webm`：失败、超时，或真实模型没有选中生日提醒时保留的原始录像，不作成功素材。
- `recording.json`：镜头时间点、创建的任务、本轮真实响应、分支是否符合预期、清理状态；不保存登录 Cookie、请求鉴权头或 API Key。

脚本只创建本次录制的生日提醒和每日巡检，录完后取消它们的后续执行，保留已发生的执行记录及审计。清理是否成功以 `recording.json` 为准。

## 安静分支

```bash
BANKPILOT_RECORD_SCENARIO=quiet npm run record:daily-review
```

这条分支不新建生日提醒，仅观察真实账户巡检。Jev 仍可能判断需要分析；脚本如实保留输出，并仅在实际跳过主模型时把该分支标记成功。不能通过硬编码概率或替换接口响应凑齐视频分支。

正式录制前应在目标环境排练，确认账号当前数据适合要展示的情节，再录主线；原始视频和 JSON 记录一起保留。
