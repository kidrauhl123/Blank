# 当场造工具（P0-2）

用户在银行 APP 的对话里用一句话描述想要的小工具，页面助手用 `build_tool` 从**审核过的积木**里生成一份工具规格，在对话里渲染成可以拖动数字的工具卡片。用户可以把它保存到首页，也可以取消保存。

工具是数字的交互界面，不是银行操作：它不转账、不申购、不改账户。

## 1. 两种积木

| 积木 | 用途 | 参数 |
|---|---|---|
| `slider-simulator` 攒钱模拟 | “每月少花多少，多久能攒够” | 标题、目标名、目标金额（100 元至 1,000 万元）、已攒金额、滑块“每月再多存”的最大值（100–5,000 元，默认 2,000）、滑块步长（50、100、200 或 500 元） |
| `split-table` 分账表 | “这次旅行和朋友怎么分账” | 标题、分账对象的姓名、分类（最多 6 个，可不填）、商户关键词（最多 6 个，可不填） |

- 攒钱模拟给出两条曲线：不变的基础月存额，和滑块调整后的月存额。计算在 `src/lib/tool-calc.ts` 的 `simulateSavings` 里完成。
- 分账表列出这位用户在所选时间段里的自己的支出（转账和理财不算，最多 200 笔；可按分类或商户关键词筛选），每一笔可以选择：**平摊**（对方承担一半，向下取整）、**不分摊**（对方不承担），或**全部由对方承担**。
  - “已收”是这段时间里对方转给你的钱：只统计备注为固定文字“来自<对方姓名>的转账”的入账。
  - 结果显示对方应付、已收和剩余金额；剩余为负表示对方多付了，需要还给对方。
  - 付款本身要在转账里完成，分账表只算账。

## 2. 规格校验

规格用 zod 的 `discriminatedUnion` 校验（`src/lib/tool-spec.ts`）：

- 标题和名称不能含数字（避免模型把数字写进界面标题）；
- 金额、步长、分类数量都有上限，超出即拒绝；
- 用户没说目标金额时，模型必须先问，不能猜。

## 3. 保存与读取

- 每位访客各有自己的工具，存在 `interactive_tools`（迁移 `034_interactive_tools.sql`）。
- 保存到首页只记下 `saved_at`；首页上的布局由界面布局表（`032_ui_layout.sql`）另外记录。
- `GET /api/v1/tools/:toolId` 返回服务端算好的基础数据，公式在前端计算。
- `POST /api/v1/tools/:toolId`，请求体 `{ "action": "save" | "unsave" }`，保存或取消保存到首页。

## 4. 边界

- `build_tool` 只在页面助手里可用，它的描述要求只在需要反复调整数字时使用；普通问答用文字回答，不用工具。
- 攒钱模拟的目标金额和已攒金额由模型从用户的话里取，用户没说就先问。这是提示词的要求，代码只校验范围。
- 分账表的金额全部来自服务端按账本算的结果。
- 分账对象按姓名查找，界面只说明找到或没找到这位演示用户，不返回对方的账户信息；没有真实的通讯录或真人身份。

## 5. 相关代码与测试

- `src/lib/tool-spec.ts`：积木规格与校验
- `src/lib/tool-calc.ts`、`src/lib/tool-calc.test.ts`：攒钱模拟、分账计算
- `src/lib/tool-store.ts`、`src/lib/tool-store.integration.test.ts`：保存、读取、取消保存（真实数据库）
- `src/app/api/v1/tools/[toolId]/route.ts`：读取与保存接口
- `src/lib/app-agent-harness.ts`：`build_tool` 工具的说明与参数
