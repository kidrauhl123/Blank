# 访客记忆归属与数据库结构

第四步于 2026-10-17 建立归属与数据库；第五步同日加入服务端读写接口；第六步将有效偏好按调用接入银行 APP 模型。设置页的偏好表单已在 `62a1ddf` 中移除，接口保留；悬浮助手现在仍可处理完整明确的偏好口令，仅在服务端提交后确认保存或删除。模型没有直接写入工具。

## 归属

成功选择演示账户时，服务端创建或复用 256 位随机访客凭据，并通过 `bankpilot_memory_visitor` HttpOnly、SameSite=Lax Cookie 返回浏览器。Cookie 仅在生产 HTTPS 下使用 Secure 属性，有效期 90 天，重新成功登录时同步续期数据库凭据。数据库只存 SHA-256 哈希，并在查询时检查服务端有效期；浏览器提交的未知、过期或格式错误的凭据不会被注册为所有者，而是换发新凭据。

`requireVisitorMemoryScope` 先验证银行会话与同源请求，再用访客凭据哈希和会话中的 `customer_id` 联合查出 `owner_id` 与演示 `profile_key`。请求体不能指定这两个值。同一浏览器切换模拟用户会保留访客凭据，但查询落在不同 profile；不同浏览器选同一模拟用户也得到不同 owner。非演示账户没有此记忆范围。浏览器清除 Cookie 后无法找回旧访客归属；此演示身份不支持跨设备同步。

## 表与约束

迁移 `015_visitor_memory.sql` 建立三张表：

| 表 | 作用 |
| --- | --- |
| `visitor_memory_owners` | 访客 ID、随机凭据哈希、创建、最近登录与服务端到期时间 |
| `visitor_memory_scopes` | `(owner_id, profile_key)` 唯一范围、启用开关与范围版本 |
| `visitor_memory_preferences` | 同一范围内每个键唯一；仅允许称呼、语言、详略；保存来源类型、更新时间、到期时间和偏好版本 |

数据库约束拒绝未知偏好键、超长称呼、不支持的语言/详略、非法来源和未晚于更新时间的到期时间。服务层进一步限制称呼格式和敏感词，只接受三类键；同一归属范围的每次写入以 `expectedVersion` 校验并在事务中锁定范围行。设置页同时带有当前访客/profile 的范围标记，避免切换模拟用户后旧设置页写入新范围。偏好保存后 90 天过期，普通读取不续期且过滤过期值；每次成功演示登录会清理已过期的偏好和访客归属。保存偏好会同步续期访客 Cookie 与服务端归属，但不会改动其他偏好的到期时间。关闭记忆后普通读取不返回任何偏好，保存会被拒绝；删除和清空仍可执行，重新启用后尚未过期且未清空的数据会再次可用。接口字段和示例见 [偏好接口](PREFERENCE_API.md)。

迁移 `016_app_agent_memory_scope.sql` 给页面助手与业务助手任务记录发起时的访客与模拟 profile；读取、恢复任务时必须一致，不能把同一共享演示账户下其他访客的任务继续运行。每次模型调用单独读取当前未过期且启用的偏好，关闭或删除后下一次调用不再注入；偏好数据不会写入共享 harness 或 checkpoint。用户消息与此前模型回复仍可能自然提及称呼，不能将删除偏好等同于清除全部会话历史。

备份里的偏好删除边界尚未确定；在明确备份保留与清除流程前，不向用户承诺备份中也已删除。登录、偏好接口与模型接线依赖迁移 015、016，因此部署须先迁移再启动新版应用；自动部署脚本检查三张表与页面任务归属列存在。该批隔离库集成测试已在 CI 与本地隔离 PostgreSQL 上执行通过；相关迁移 015、016 已随 `2a56ca3` 部署到生产。
