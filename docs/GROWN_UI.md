# 生长式界面：用户自己长出来的 Blank

Blank 的界面可以由用户和 AI 在对话里一起改：首页怎么排、底部导航放什么、再添自己的页面。原则是 **AI 不写界面代码，只用审核过的积木按“排版语法”组装；模板本身是数据（JSON）；界面结构的任何变化都必须用户在 APP 里确认才生效。** 默认配置等于原来的界面（资产卡置顶 + 全部动态，底栏首页 / 理财 / Blank / 明细 / 卡片），老页面原样保留为“系统页面”。

## 三层
- **排版语法**（`src/lib/ui-schema.ts`）：布局 = 首页区块（资产卡、一组动态帖子）+ 底部导航（≤5 项，首页和 Blank 必须保留）；页面 = 1–6 个面板，每个面板一份查询 + 1–3 块积木（大数字、趋势、排行、日历、明细、环比、备注）。设计规范写在语法里，违反的方案提交不了：半宽面板只能放大数字或备注且必须两个相邻成对；页面名、面板标题和备注里不能写数字；面板标题不能重复；页面不超过 8 个。
- **积木**：复用动态卡片配方的积木与查询（`feed-recipe.ts`），数字全部由服务端按账本计算。为“和某位朋友的往来”这类页面，查询新增了 `direction: both` 和大数字 `net`（净额）。
- **技能**（`bank-ui-design`，`app-agent-skills.ts`）：设计规范、语法说明、三个页面原型（专题追踪页、月度总览页、往来页）和“做不到时怎么办”。

## 提案与确认
模型有五个界面工具：`list_ui`（读现状和编号）、`propose_layout`、`propose_page`（可同时提议放进导航，或用 `replaces` 修改已有页面）、`propose_remove_page`、`note_unmet_need`。另有 `build_tool`，用同样的积木审核方式当场生成小工具，见 [当场造工具](INTERACTIVE_TOOLS.md)。提案写进 `ui_proposals`，对话里渲染成预览卡片（布局给出首页顺序和导航，页面直接渲染出真数据）。**只有用户点卡片上的“应用 / 不要”才改变界面**——这是用户本人对 `POST /api/v1/ui/proposals/:id` 的同源点击，模型没有任何工具能代点；这也是和动态卡片、定时任务（模型确认后 `save_*`）的不同之处，因为界面结构变化更值得由本人确认。

## 数据与隔离
迁移 `032_ui_layout.sql`：`ui_layouts`、`ui_pages`、`ui_proposals`、`ui_unmet_needs`。演示账户由访客共用，所以全部按访客隔离：别的访客看不到你的页面和布局，也不能决定你的提案。

## 做不到的需求
现有积木表达不了的需求（实时行情和资讯、子账户和存钱罐、预算进度条、深色和大字模式、地图……）：模型调用 `note_unmet_need` 记到 `ui_unmet_needs`，仍用最接近的方式做出能做的部分，并如实告诉用户哪里没做到。开发汇总这张表，决定补哪些新积木；新积木是代码，审核后进入积木库，所有用户可用。
