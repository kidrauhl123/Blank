# BankPilot UI 重构准备

基线：`main / a220ee5`，2026-10-13。规范：JungUI 设计规范（本地技能库 `JungUI/skills/jungui/SKILL.md`，不在本仓库内）。本次产物是源码审计、视觉方向和静态交互草案；尚未修改业务页面或完成浏览器视觉验收。

## 方向

轻量、清楚、适合手机的银行工具。资产和流水是主角，AI 入口保持稳定。保留紫色作为唯一主色，文字与背景改用真正的中性灰；通过留白、字重和对齐组织信息。

首页余额直接排在页面上，不围框。月度概览和流水以段落、行分隔线组织。卡片管理中的卡片用单一底色区分，不叠描边、渐变和投影。手机单列、左右 16px；桌面使用实际页面宽度，不再把应用缩进 430px 的手机模型。

静态草案：[打开 HTML](../ui-refactor-draft/index.html)。所有金额、卡号、交易均为草案示例，未连接银行、数据库或模型。可切换首页、AI 助手、明细、卡片，查看转账表单和隐藏余额；不是银行业务或 Agent 验收。

## 页面与容器决策

| 区域 | 边界手段 | 信息结构 |
| --- | --- | --- |
| 首页资产 | 无容器 | 问候 → 资产标签/隐藏 → 金额 → 账户 → 转账/入金 |
| 月度概览 | 无容器 | 本月金额 → 日期 → 分类行；不写成预算或占比仪表盘 |
| 首页/明细流水 | 无容器、行分隔 | 对象与时间左对齐，金额右对齐；近期 50 笔与完整月账单明确区分 |
| 卡片实体 | 仅色差 | 单一中性底色，状态单独标明；全卡点击只打开管理详情 |
| 用户入口 | 无容器、行分隔 | 五位用户整行可选；共享模拟身份说明保留 |
| 业务表单 | 控件仅边框 | 对象、金额、风险和确认状态清楚；每步只有一个主按钮 |
| 助手 | 无容器回复，用户消息仅色差 | 单一会话；许可、暂停、继续、执行记录分清层级 |
| 安全/渠道设置 | 无容器、行分隔 | 二级页返回，设置行与必要输入；状态色只表达真实状态 |
| 真正模态弹窗 | 浅色仅阴影；深色仅边框 | 半透明遮罩是模态语义；面板不叠多种边界；保留焦点陷阱和恢复 |

## Token 契约

- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48；手机页面左右 16。
- 字号：12 / 14 / 16 / 20 / 24。手机正文和输入 ≥16；资产金额 24，通过字重、留白和 tabular-nums 强调。
- 圆角：8 / 16。图标和步骤标记也沿用这两档，不引入独立胶囊圆角。
- 主色：紫色；其它界面用中性灰。成功、警告、错误仅表达状态。头像不再内联传任意主题色。
- 正文、金额、控件文本对比度 ≥4.5:1；输入边界及焦点 ≥3:1。草案主色浅色 `#6d28d9`，深色 `#c4b5fd`，最终逐状态核验。
- 点击区至少 44px；相邻点击区间距 ≥8；桌面 hover 只在 `@media (hover: hover)` 生效；手机按下只改变底色/透明度。
- 只保留功能性动效，150–250ms，只改变颜色/透明度/高度；尊重 reduced-motion。
- 页面高度用 `100dvh`；固定导航考虑底部安全区；输入、底部按钮须通过真实键盘遮挡检查。
- `surface`、`text`、`muted`、`line`、`field-line`、`accent`、状态色、`scrim`、浮层边界/阴影统一在主题变量层维护。

## 实施顺序

1. **基础与首页**：更新设计系统和全局 token；改 `BankingApp` 页面壳、首页和 `AuthScreen`；调整明细行、导航及桌面布局。保留现有业务流程。
2. **表单与卡片**：统一 `BankDialog`、按钮、输入、确认摘要、回执和错误状态；去掉 `LiquidBankCard` 装饰。保留 Escape、Tab 焦点循环、关闭后恢复焦点与 busy 禁止关闭。
3. **助手**：在现有 `FloatingAppAgent` 中改面板和状态展示。静态草案使用独立助手页面探索布局，接入时必须保留同一会话及可见页面控制、许可、暂停和恢复，不重新实现 Agent。
4. **辅助页**：渠道、安全、审计、交互预览对齐同一套页面壳和组件；移除已确定不再使用的样式，更新说明。
5. **视觉及交互验收**：完成下列矩阵后再合并发布。

不要先重写整份 `BankingApp.tsx` 的业务状态机。初期提取公共视图组件即可；转账、授权、资金提交和 Agent 协议保持原契约。

## 必须保护的交互契约

- 保留 `data-agent-page`、`data-agent-viewport`、`data-agent-id`、`data-agent-permission` 和必要 label；控件移动后重新观察、重新定位。
- `human` 确认按钮不能因重构变为 Agent 可点击；草稿、黄色确认、红色 TOTP、提交中禁用和未知结果提示保留。
- 查询失败不显示零余额；账户余额与卡片额度区分；银行回执不由助手文案替代。
- 助手返回再打开仍是同一会话；用户干预立即暂停，继续前重新观察；不让新的浮层遮挡操作目标。
- 五用户选择、个人中心切换、安全/渠道/审计返回都可达；共享测试数据说明保留。

## 验收矩阵

| 维度 | 样本 / 条件 |
| --- | --- |
| 设备 | 手机 360×800、390×844、430×932；平板 768×1024；桌面 1440×900 |
| 主题与缩放 | 系统浅色/深色；200% 缩放；长中文名、长金额、长交易名 |
| 状态 | 初次加载、刷新旧数据、真零余额、空列表、服务不可用、提交中、结果未知、成功回执 |
| 表单 | 手机键盘弹出、金额输入、TOTP；主按钮与焦点可见，无横向滚动 |
| 对话 | 长回复、选择题、用户输入、许可、暂停、继续、失败；浮层不挡业务按钮 |
| 无障碍 | Tab 顺序、可见焦点、模态 Escape/焦点恢复、状态读出、色彩对比 |
| 回归 | `npm run lint`、`npm test`、`npm run build`；相关 `banking-ux`、`visible-agent`、`interaction-preview`、`transfer-quota` 浏览器用例 |
