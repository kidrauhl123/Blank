# 定时任务

入口：Blank 页面右上角的「定时任务」图标，或 `/schedules`。

支持自定义提醒、上一个自然月的账面收支报告、未来 72 小时的订阅到期检查、分类预算提醒（`BUDGET_CHECK`，迁移 039），以及每日 AI 巡检；支持一次性、每日、每周、每月执行。月度报告固定按月，预算提醒和 AI 巡检固定按天。只读任务不执行转账、申购、扣款或商户订单。预算提醒的规则见 [Skills 库](SKILLS_LIBRARY.md) 的“预算提醒”一节。AI 巡检的 Jev 判断、主模型调用和配置见 [Jev 每日 AI 巡检](DAILY_AI_REVIEWS.md)。

任务只能在和 Blank 的对话里创建（2026-10-29 起，手动表单和 `POST /api/v1/schedules` 已移除）：用户用一句话描述，Blank 用 `preview_schedule` 设计草稿并在对话里渲染预览卡片（重复规则、第一次执行时间、用当前账本现算的样例），用户在 `ask_user` 里选“创建任务”后 `save_schedule` 才让它生效。草稿（状态 `DRAFT`）不会被调度器执行，也不出现在任何列表里；一天后未确认的草稿会被清理。时间用“北京时间的日期 + 钟点”描述，由服务端换算；系统在每次模型调用里提供当前时间。月度报告固定按月、每日巡检固定按天。

对话里创建的任务只属于创建它的访客（演示账户由访客共用）：只有他能看到、暂停、恢复和取消，结果也只发给他。聊天渠道通知不在对话里开放，结果发到首页动态（`kind=schedule`，每次执行一条；每日巡检只在有关注事项时发），也可以在 `/schedules` 查看。`/schedules` 只保留列表、结果、暂停、恢复和取消。工具：`preview_schedule`、`save_schedule`、`list_schedules`、`change_schedule`（取消前先确认）。迁移 `031_schedule_chat.sql`。

可以暂停、恢复和取消，APP 保留最近执行结果。任务不是页面计时器：关闭网页仍由独立 Worker 调用受专用凭据保护的内部接口执行。

## 时间与恢复

- 首版只支持 `Asia/Shanghai`。日期输入按北京时间解释，与浏览器所在时区无关。
- 每周沿用首次星期和时间；每月沿用首次日期，短月取最后一天，下月恢复原日号。
- 服务停机期间任务不会丢失。恢复后每个逾期任务补跑一次，周期任务随后跳到未来的下一个周期，不批量补发历史提醒。
- 月报统计原定执行日期前一个自然月；订阅检查使用实际执行时间未来 72 小时。
- 暂停期间不执行。恢复周期任务跳过暂停期间的周期；已过期的一次性提醒恢复后执行一次。超过截止时间的任务结束，不再补跑。
- 取消或暂停与执行争用同一行锁：先完成的一方决定本轮是否已经生成结果。已生成的结果及通知队列不会撤回，取消只阻止后续执行。
- 每次扫描最多处理 10 个任务。事务回滚后可重试；失败间隔为 60/120 秒，第三次失败后进入 ERROR，用户可恢复。后台每 15 秒扫描，非精确到秒的实时调度。

## 数据与通知

账户归属取自已认证会话，用户不能在请求中指定客户号。创建有客户级数量限制和幂等键，写接口检查同源。任务领取使用数据库行锁和 SKIP LOCKED；普通只读任务的本轮回执、下次时间和通知入队在同一事务内提交。提醒、月度报告、订阅检查和预算提醒这四类只读任务不调用模型，也不执行用户脚本。每日 AI 巡检先在该事务内排队，再由带租约的独立领取流程在事务外调用 Jev 和必要的主模型；没有资金工具。

月报复用整月账单服务，明确显示账面流入/流出（包含转账），不将其称为消费。订阅到期日期来自现有订阅记录，不代表已验证商户续费计划；没有到期记录时不发聊天通知。

所有结果默认保存在 APP。用户可明确选择一个已绑定 QQ/企微身份，外部消息仅提示有新结果，不携带金额或提醒正文。执行时重验绑定归属和状态，解绑后只保留 APP 结果。通知通过现有 outbox 发送，页面显示待发送/重试/已发送/重试耗尽。任务完成不等于消息送达；平台主动消息限制和机器人连接状态需分别联调。

## 本地启动

1. 应用所有迁移（包括 `020_scheduled_tasks.sql`）：`npm run db:migrate`。
2. 在私有 `.env.local` 中设置 `SCHEDULER_TOKEN` 为独立的至少 32 字符随机值（可用 `openssl rand -hex 32` 生成）。不要复用 QQ/企微或模型密钥。
3. 启动 APP：`npm run dev`。
4. 另开终端：`npm run scheduler:dev`。默认连接 `http://127.0.0.1:3000`；其他地址设置 `BANKPILOT_INTERNAL_URL`。
5. 打开任务页，确认“后台调度暂未就绪”提示消失。创建未来几分钟的一次性提醒验证完整流程。

内部接口：`POST /api/internal/scheduler/tick`，仅接受专用 Bearer 凭据。银行 Cookie、QQ/企微令牌不能代替。调用者不能指定运行时间、客户号或任务类型。
用户接口（仅接受银行会话）：
- `GET /api/v1/schedules`：列表与最近结果；`PATCH`：暂停、恢复、取消。没有 `POST`，任务只能在对话里创建。
- `GET /api/v1/schedules/drafts/:scheduleId`：草稿预览。
- `POST /api/v1/schedules/review-now`：手动运行一次每日 AI 巡检，需要已启用的巡检任务，24 小时内最多 12 次。规则见 [Jev 每日 AI 巡检](DAILY_AI_REVIEWS.md)。

## 部署

Compose 增加 `scheduler` 服务，与 APP 共用私有的 `SCHEDULER_TOKEN`。执行迁移后启动 `app scheduler`。自动部署脚本会在首次升级时生成凭据、停止旧调度器、迁移后启动新服务；未执行发布就不会改变线上实例。手动部署必须自行填写私有环境变量。

页面从数据库心跳判断最近 90 秒内是否成功扫描；未配置、退出或长时间不可达时会显示未就绪，不宣称任务已按时执行。

## 验证

- 日历单元测试：短月、闰年、北京时间跨月、跳过漏跑周期、一次性任务、输入和凭据校验。
- PostgreSQL 集成测试：客户隔离、重复创建、并发扫描、暂停/恢复/取消、完整账单、解绑、截止时间、失败重试、事务回滚恢复和 HTTP 权限。
- 浏览器测试：创建与确认、月报频率、暂停/取消及执行结果展示。

使用隔离 `bankpilot_test` 数据库运行 `BANKPILOT_DB_TESTS=1 npm test -- --no-file-parallelism`，禁止测试连接正式共享账户库。
