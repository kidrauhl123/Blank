# 对话与页面接管

正式入口是底栏第五个页面 AI 助手，与首页、理财、明细和卡片共用同一个 Tab 状态。对话通过页面容器的正常 flex 布局显示，不使用绝对定位面板、返回按钮或遮罩。助手控制器持续挂载，对话 DOM 在切换 Tab 时保留。只有执行接管操作时才使用触点和控制条覆盖层。

查询余额、月度账单、支出分类、订阅与持仓时，使用只读的 read_bank_facts，产品筛选比较使用 search_investment_products，直接在对话中回复。完整月度账单使用 statement 汇总，支持 YYYY-MM；不能用近期流水替代整月统计。工具仅接受数据范围，客户身份由已登录会话注入，模型不能指定其他客户。

用户明确要求打开页面，或需要转账、开卡、锁卡、理财申赎等准备办理时，才进入页面接管。用户允许后，显示对应银行页面，让用户直接看导航、滚动、点击和逐字填表。触点保留上一个位置，下一次操作时移动到真实控件；弹窗内的动作与暂停控制也保持可见。最终确认或验证码由本人完成，准备好确认页后不再用聊天遮住表单。

这借鉴 [BrowserSkill](https://github.com/Tencent/BrowserSkill) 的可见操作体验。当前执行器使用本应用注册的 DOM 控件和权限，并未安装它的浏览器扩展或通用浏览器控制服务。页面动作由模型根据最新快照决定，前端调用实际控件，不播放预录动画。用户触碰银行页面即暂停；继续会重新读取页面。

操作记录默认折叠，只用于回看，不承担实时操作展示。

## 文本回复

`react-markdown` + `remark-gfm` 渲染段落、标题、强调、列表、引用、代码和可横向滚动的表格。原始 HTML 不执行，图片不自动请求外部地址，链接保留默认安全 URL 处理。

`POST /api/agent/app` 根据 `Accept: text/event-stream` 返回 SSE。服务端在原有 LangGraph 调用中接收模型的文字 token 回调，发送 `text-start`、`text-delta`、`text-end`，最后发送包含权威任务状态的 `result`。工具调用参数、推理内容、密钥不进入文字事件。既有 JSON 客户端保留原协议。

前端按 UTF-8 流解码并处理跨分块的 SSE 事件；回复到达时立即渲染 Markdown。每个模型回复有独立 ID，最终结果替换临时回复，不重复显示。停止生成或断开请求会取消服务端模型调用。用户上滑查看旧消息时不强制拉回底部。
