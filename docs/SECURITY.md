# 安全设计与自评

## 权限分级

| 级别 | 当前执行策略 | 示例 |
|---|---|---|
| GREEN | 意图确认后自动查询 | 余额、流水、账单、卡片、订阅、已核验产品 |
| YELLOW | 展示金额、对象、影响、操作编号后明确确认 | 小额转账、虚拟卡申请、锁卡 |
| RED | TOTP 时间步消费；单挑战三次失败锁定，客户级三次失败冷却 15 分钟 | 日累计超过 ¥1,000；新设备登录后 24 小时内的转账（不可信设备）；30 分钟内强验证失败三次以上；反诈守护暂缓（见 [反诈守护](FRAUD_GUARD.md)） |

对外 MCP、OpenAPI、开发者中心和客户 API 令牌已退役。银行 APP 接口只接受会话，任何 Authorization 头均拒绝；旧令牌不能读取或创建草稿。历史凭据全部撤销归档，旧调用审计保留，见 [外部接入退役](EXTERNAL_ACCESS_RETIREMENT.md)。

QQ 与企业微信属于受控用户渠道而不是新的银行核心。黄色操作可在绑定身份的原生按钮内明确确认；红色操作只能跳转 Blank，并由现有银行会话 + TOTP 完成。不同渠道身份、任务 ID 与操作 ID 必须同时匹配。

## 已实现控制

- 演示身份：只允许五个固定模拟 profile key；注册与密码登录 HTTP 路由已移除。这些是公开共享测试身份，不用于验证真实客户身份。
- 会话：256 位随机不透明令牌，仅保存 SHA-256 摘要；HttpOnly、Secure（生产）、SameSite=Lax、7 天过期、可撤销。
- 模型设置：设置绑定当前银行会话，目录只返回模型 ID，服务端密钥不下发。新任务记录模型并在恢复时沿用，换模型不改变银行授权边界。见 [模型设置](MODEL_SETTINGS.md)。
- MFA：RFC 6238 TOTP，服务端密钥以 AES-256-GCM 加密；允许前后一个 30 秒窗口。在客户锁内消费时间步，首次绑定与转账共用客户级失败预算，三次失败冷却 15 分钟；同一步不能授权第二笔交易。
- CSRF：Cookie 写操作必须携带正式 APP 的完整 Origin；不允许 Bearer 豁免，不依赖 Host/x-forwarded-host 授权。普通 GET/HEAD 可无 Origin，仍需银行会话。
- 数据隔离：所有客户查询和写入都带已认证 `customer_id`，历史外部审计也按客户隔离。
- Prompt Injection：用户文本被视为不可信数据；模型仅能输出固定 Schema；工具与策略层不接受模型越权指令。
- 外部内容防护（2026-11-01）：备注、商户名、资讯、IM 消息、Blank 互联消息等外部内容进入模型前标为不可信数据（`untrustedData`），工具返回的外部结果同样标注。查询轮不能调用办理类工具（`classifyTurn`、`intentMismatch`）；写操作只认用户本人打字的话；页面助手的提问不索取验证码（`guardSecretQuestion`）。
- 业务回执：工作流使用类型化服务端事实生成余额、金额和状态，不再由第二次模型自由生成。未配置 AI 时意图理解仍直接失败。页面助手的动作描述和追问不构成银行回执，详见 [补强与验证边界](AUTHORIZATION_HARDENING.md)。
- 资金完整性：数据库事务、行锁、正整数金额、非负客户余额、唯一操作编号、平衡双分录。
- 转账累计：提交事务以客户为粒度串行，锁等待后按数据库时间重算上海当日成功金额；超过 1000 元的黄色草稿持久化升级 RED/MFA 并暂停，APP/IM 均不提前报告成功。见 [提交时日累计校验](TRANSFER_QUOTA.md)。
- 审计：模拟用户初始化、用户选择、入金、转账准备/成功、MFA、卡片和 Agent 任务均留痕；旧外部凭据/调用历史保留。
- 代码沙箱：系统不向 LLM 暴露代码执行、Shell、SQL 或任意网络请求工具，因此当前没有模型生成代码的执行面。
- 数据最小化：卡片只保存脱敏尾号；密码、TOTP 动态码和原始 API 令牌不写入日志。
- 持久化 Agent：LangGraph checkpoint 独立 schema；业务租户关系由 Blank 表维护，不信任 checkpoint 内的 customer id。
- 渠道隔离：QQ openid 与企业微信 userid 使用 AES-256-GCM 加密、HMAC 索引；Bot Secret 仅在对应 Worker，内部 API 使用互不通用的随机 Bearer。
- QQ 隐私边界：群聊消息不调用模型、不查询账户、不创建操作；仅 C2C 私聊可以进入银行 Agent。
- 防重与投递：入站 `msgid` 唯一；授权恢复以数据库状态原子抢占；最终消息使用 outbox，失败退避重试且最多 8 次。
- 链接安全：绑定 secret 放在 URL fragment，不进入 Web 服务器请求日志；令牌一次性、10 分钟过期。

## 异常与回退

黄色和红色转账草稿均在数据库时间起算 10 分钟后过期，红色授权挑战不得延长该期限。同一挑战连续 3 次失败锁定，客户级连续 3 次失败冷却 15 分钟，缺少验证码不消耗尝试。提交时从黄色升级会持久化新挑战，沿用草稿期限。提交前重算指纹，金额、对象、币种、备注或期限变化会拒绝执行。余额不足、账户状态异常或对象归属不一致时，核心拒绝执行。数据库异常会回滚整笔账本事务和动态码消费；明确认证失败的计数仍会提交。摘要不是客户签名，不能抵御能同时改写数据和摘要的数据库管理员。新控制需先执行 019，已在隔离 PostgreSQL 17 完成数据库回归。

Agent 任务和每个 DAG 节点均有状态字段，可进入 `NEEDS_INPUT`、`AWAITING_AUTH`、`SUCCEEDED` 等状态。LangGraph 写操作会停在持久化中断点，PWA 支持显式取消，服务重启后仍可恢复。银行操作已经成功但最终文案暂时失败时，核心结果不回滚；审计记录 `AGENT_RESUME_DEFERRED`，不得把它误报为资金失败。

## 已知风险

依赖审计（2026-10-11）：Next.js 升至 16.3.8，sharp 至 0.35.5、source-map-js 至 1.2.2，移除 MCP SDK 后核对生产依赖。Next 修复范围参考 [官方安全公告](https://github.com/advisories/GHSA-mcj8-r9mp-w47p)。`npm audit --omit=dev` 仍报告 4 个 high 项，来源为 Deep Agents → fast-glob / micromatch / braces 链；[braces 公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) 暂无修复版本。当前页面工具禁用 glob/grep/ls，read_file 只允许固定技能文件；这缩小输入面，不代表依赖漏洞已修复。继续跟踪上游，不通过将 SDK 降到旧版 0.0.2 消除告警。

- 比赛沙箱不连接真实 KYC、AML、制裁筛查、银行卡清算、短信、人脸或 U 盾系统。
- 审计记录位于主 PostgreSQL，尚未同步到 WORM/独立 SIEM。
- TOTP 初始密钥由用户复制到身份验证器（安全中心显示密钥，没有二维码），也没有恢复码。
- 设备只按操作系统和浏览器粗略区分（见 [反诈守护](FRAUD_GUARD.md) 第 4 节），不是设备绑定，也没有风险画像。
- TOTP 时间步消费、客户级失败冷却已实现：客户锁内消费时间步，首次绑定与转账共用客户级失败预算，三次失败冷却 15 分钟。换绑与恢复仍缺失。
- 工作流已采用服务端事实回执；页面助手的追问和动作描述仍是模型输出，无银行回执时的成功措辞已受服务端保护，页面动作完成不能当作银行业务回执。
- 理财只有六只明确标注为模拟的产品（见 [模拟理财](SIMULATED_INVESTMENTS.md)），没有接入真实理财数据，也没有真实申购。
- QQ 与企业微信 Bot 凭据需在各自腾讯开放平台创建；没有凭据时对应 Worker profile 保持关闭，APP 可独立运行。
- 渠道 outbox 达到 8 次失败后保留为 `FAILED`，目前需要运维审计与人工重放，尚未接入独立告警平台。

这些限制会在答辩中明确，不将比赛沙箱描述为可直接承载真实资金的生产银行。

## 2026-11-01 P1 安全补强

- 新增的安全控制：新设备与失败次数进入转账风险（[反诈守护](FRAUD_GUARD.md)、[立规矩](WALLET_RULES.md)）；Blank 互联只传授权范围内的固定字段，收到的消息只当数据展示（[Blank 互联](BLANK_LINK.md)）；做法只能由用户本人创建，且不能改变权限（[Skills 库](SKILLS_LIBRARY.md)）；IM 里只能在 App 完成的请求只回链接，不尝试执行（[渠道接入](CHANNEL_ONBOARDING.md)）。
- 提示词注入：`docs/security-reports/2026-10-17/corpus/prompt-injection.jsonl` 的 12 条语料加上备注、商户名、IM、互联消息和多轮用例，全部是确定性检查，已纳入 `src/lib/prompt-injection.regression.test.ts`。结果和逐条说明见 [提示词注入回归](security-reports/2026-11-01/prompt-injection-regression.md)。
- **未完成**：真实模型 20 例评测和人工复核这次没有运行，因为本机没有模型密钥。那些检查证明服务端闸门在模型越权时仍然有效，但模型会不会听从注入，需要真实模型跑过才知道。
- 已知限制：意图一致性是关键词判断，宁可放行办理，不误伤办理；资讯规则没有来源，只是预留。
